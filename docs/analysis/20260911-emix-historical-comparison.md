**Bread Basket：有历史优势，但最清楚的变化是baseline从新视角获益，EMIX没有同步获益。**

右广角200ep→俯视200ep：baseline26→42，EMIX33→31，差值+7→−11。当前500ep的EMIX37其实高于历史右广角33，只是baseline也上升到了45。所以这里的“回退”主要指相对baseline的收益消失，不能解释成EMIX模型绝对成功率一直下降。

|---|---:|---:|---:|---:|
|可训练配对数|28,543|24,950|29,502|495,345|
|home3cm内端点占比|66.0%|64.0%|60.8%|68.8%|

|释放窗口占比|1.06%|1.03%|1.28%|1.02%|

从右广角到俯视200ep，home集中程度反而略降，抓取窗口略升，但收益从+7翻到−11。跨阶段增加约2.9个百分点可能有贡献，却不足以据此解释18点收益变化。前三列的主要训练配置相同，数据分布指标相近；**应把“视角与混合图像的交互”提到比单纯home集中更高的位置。**

在四个run共同拥有的98个评测seed上：右广角26/98→33/98，俯视42/98→30/98，翻转仍存在，不能仅由那几个不同的评测seed解释。这仍不是完全隔离相机的因果实验：训练数据各自采集，仿真、训练随机性未重复控制。

查看相同seed首帧，右广角中部分场景的篮子/物体靠近画面左缘，俯视中布局更居中、对象位置关系更直接可见。[相同seed机位对照](../../outputs/analysis/history_20260911/place_bread_basket_views.jpg)。可行猜想是：更清楚的真实图像让baseline利用了对象位置和已完成状态；整图混合同时叠加不同篮子/面包配置，限制EMIX利用这些新增的清晰信息。尚未量化遮挡、目标像素大小或状态可辨性，不能把这一机制视为已证明。

另外，从俯视200到500，放宽姿态门限后的可训练组数增加约16.8倍，抓取窗口权重却从5.74%降到0.77%。这说明“更多配对”并未增加关键操作窗口的相对曝光。该稀释可能解释扩大数据后仍有负差，但不能解释更早右广角→俯视200的翻转，因为那时阈值相同。

优先验证：同一批专家轨迹同步保存右广角/俯视两路图像，使用完全相同的端点配对、数据顺序和评测场景，做视角×baseline/EMIX的2×2对照；再加弱混合alpha或同阶段配对，看哪项恢复俯视下EMIX对第二轮操作的利用。

近侧→俯视200ep：baseline15→23，EMIX27→21；在四个run共同99个seed中结果也是15→27与23→21。两个视角的布局像素尺度、相机投影和遮挡关系不同：[首帧对照](../../outputs/analysis/history_20260911/blocks_ranking_rgb_views.jpg)。合理猜想是home处图像混合在某个视角提供更有效的布局/外观正则化，而在另一个视角弱化颜色对象、排列进度或空间关系；但本次没有证据判断到底是颜色、位置还是进度通道受影响。

优先验证与Bread相同的多机位、同轨迹同配对实验；增加alpha强度对照。避免首先简单删除home样本，因为历史正向RGB恰好在96%的home权重下发生。

**Stack Blocks：曾有+5，但旧任务条件改变较多，目前不能把原因锁定到EMIX。**

08-20旧批为65→70；后续近侧35→32、右广角49→43、俯视200ep45→35、俯视500ep49→45。旧批的baseline与EMIX有100个共同评测seed，旧批+5的精确McNemar p=0.522；相同seed并不意味着旧/新任务布置相同。

两方法在旧批都比cen_arm批更高。首帧可直接看到旧批与居中工作区的物体相对机器人位置、分布范围不同；旧批和后续右广角虽然相机规格关系接近，不能当作同一任务分布。[旧/新首帧](../../outputs/analysis/history_20260911/stack_blocks_two_views.jpg)。08-20 scheduler还是0.8→0，后续0.6→0，因而不能用“现在混合概率更大”解释旧正新负。

三个200ep cen_arm批的有效索引非常少：3,209 / 3,386 / 3,519组，原始帧覆盖仅2.7–3.0%，并且都负向。当前500ep有498,268组、覆盖45.2%，释放窗口占比由俯视200ep的0.51%提升至5.20%，负差从−10缩小到−4。这支持“旧cen_arm索引覆盖不足，扩容后有所缓解”的猜想，但数据量、姿态门限、cap共同改变，无法确定各自贡献。原始数据释放窗口约14.8%，当前EMIX仍明显低于它。

可行解释是任务空间/视觉条件变难后，原有增广不能补足精确放置瓶颈；增加候选让情况改善，但没有解决接触末段。旧+5也可能包含评测/训练波动。由于08-20没有对应data/index，本次没有计算它的完整阶段分布，不应据当前或其他批索引倒推旧批。

优先验证：先在当前任务固定500ep数据，只改变旧0.01与新0.26门限、并分别控制阶段分布，记录首次搬运/第二次叠放/最终高度与横向误差。只有找到旧批真正数据及任务版本后，才做旧几何与新几何的对照。

**这些历史优势有多可信？**

|历史正向例子|共同seed数量|共同集baseline→EMIX成功数|精确McNemar p|
|---|---:|---:|---:|
|Bread右广角|98|26→33|0.296|
|RGB近侧|99|15→27|0.050102|
|Stack旧08-20|100|65→70|0.522|

应称它们为“历史正向观察”，不是稳定优势的证明。当前证据最适合指导消融：优先做Bread/RGB的视角×混合对照；Stack优先做固定任务数据下的索引门限/操作窗口曝光对照。所有结果至少用多训练seed、固定评测场景清单复核。

这也修正了[进度记录](../prog/prog.md)中“相机本身无影响，因为配对在EEF空间”的推断：**配对生成不依赖相机，不代表图像混合的训练效果不依赖相机。** 本次历史分布对比恰好说明不能从前者推出后者。
